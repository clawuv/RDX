# P1 BGRA 软编码接入

为 Windows 捕获接入补齐数据路径，尚未实现 Desktop Duplication 或显示器枚举。

- CapturedFrame::from_bgra_rows 接收顶部向下的 BGRA 字节、行跨度、尺寸和时间戳；排除行尾填充，输出紧密排列帧。最后一行无需额外 padding。
- 校验零尺寸、短缓冲、过小 row pitch 和整数溢出；显式分配失败返回错误。damage 暂为空，表示整帧刷新。
- OpenH264Encoder 接受紧密 BGRA，复用 openh264 0.9.8 的 YUVBuffer/read_bgra8 转换；尺寸变化重建缓冲。原 I420 借用路径保留，NV12 暂不支持。
- BGRA 和 I420 的 4:2:0 编码均拒绝零或奇数尺寸；奇数屏幕尺寸的裁剪/填充策略留给捕获适配层显式决定。
- 这是 CPU 回退路径：平台映射缓冲紧缩拷贝一次，再进行 CPU BGRA→I420 转换；不是零拷贝或硬编。

聚焦验证：rd-capture 5 项、rd-codec 5 项测试通过。新增检查覆盖行填充剔除、时间戳保留、非法尺寸/跨度/缓冲、真实 H.264 编解码中的红蓝颜色和 128×96→64×64 分辨率变化。颜色断言允许编码量化误差；未测实际屏幕采集性能。
