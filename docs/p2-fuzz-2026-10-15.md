# P2 协议模糊测试与 CI（2026-10-15）

独立 fuzz 工程已替换占位目录；主 workspace exclude 此工程，以免默认桌面构建依赖 libFuzzer。独立 Cargo.lock 锁定依赖，主工作区沿用原锁文件。

目标使用同一输入检查 FrameHeader、Frame、ControlMessage 和有状态 Reassembler。检查合法裸帧编码与原消费前缀一致、解析失败零消费、控制消息语义往返、重组缓存峰值不超过 MAX_BUFFERED，以及最终推进 TTL 后缓存归零。分片输入由时间增量与长度前缀分隔，便于变异多包操作。初始种子覆盖合法帧、控制请求、完成分片、重放、部分帧过期和畸形包；原有单元测试继续覆盖最大帧与容量边界。

本机 Windows 1.95 验证：种子逐字节取反和逐字节截断测试 1 项通过，fuzz 工程 all-targets 严格 clippy 与独立格式检查通过。尝试直接运行 libFuzzer 二进制遇到 MSVC LNK1561（入口未定义）；未声称本机已运行覆盖率引导模糊测试或 ASan。

CI 新增 Linux nightly 任务，安装固定 cargo-fuzz 0.13.1，先运行种子回归，再执行 30 秒模糊冒烟；输入上限 64KiB、RSS 上限 512MiB、单输入超时 5 秒。失败时上传 artifacts。已核对 cargo-fuzz CLI 源码，run 不接受 --locked；依赖锁定检查由前置 cargo test --locked 完成。CI 尚未在远端运行，Linux nightly/ASan 验证结果仍待回填。

CI 另新增 Windows WebRTC feature 定向回归和严格 clippy，避免默认 feature 跳过传输实现。本机相同命令 63 项测试通过（app 28、engine 11、protocol 13、transport 11），对应严格 clippy 通过；主工作区格式与 diff 检查通过。

信令协议及 broker IPC 尚无实现，因此未添加虚假目标。此次不冻结协议，也不代表长期模糊测试、安全审计、跨机或 P2 整体验收通过；P1 仍暂缓。
