# macOS ScreenCaptureKit 接入基线

## 本轮实现

- 将仓库中未注册、未参与构建的 macos_sck 后端接入 rd-capture；依赖仅在 macOS 编译。
- 复用 RDX_CAPTURE_DISPLAY 显式选择本次显示器枚举的索引。未设置时继续使用合成源；非法索引报错，不回退至其他屏幕。
- SC 输出 420v/NV12，回调去行填充并去交织为 I420，复用现有 H.264 软编/软解与 GPU YUV 上传。仍有 CPU 拷贝，不是硬编或零拷贝。
- 用 watch 单槽替代四帧 FIFO，慢消费者读取最新画面。100ms 等待超时允许管道定期检查关闭，不把静态桌面未出帧判断为权限错误。
- 时间戳采用回环共用的 Instant，记录于 CPU 像素转换前；不代表桌面原始生成时刻或 GPU 呈现完成。
- 去掉本地 unsafe Send 声明，使用依赖自身的 SCStream Send 实现；检查平面高度、行跨度及尺寸乘法溢出。
- 输出尺寸变化返回 DisplayChanged；重建先释放旧流，再按原 display_id 精确匹配显示器，保持采集参数和共用时钟。原显示器缺失或 ID 重复则拒绝恢复，不以旧索引选取其他屏幕。现有管道有最多五次退避重试，耗尽后停止。display_id 只用于本次会话，不保证跨重启的永久身份。
- 接入原生流停止错误回调，优先报告错误而不是继续消费旧帧或永久超时。未区分可恢复的原生错误码，因此此类错误保守停止，权限撤销不自动重试。固定输出尺寸下的真实分辨率变化是否触发尺寸事件仍待实机验证。

## 手动验证入口

单帧探针（只输出尺寸/字节数/时间戳，不保存桌面像素）：

```sh
cargo run -p rd-capture --example macos_probe --locked -- 0
```

主动重建探针（采集前后各一帧，验证时钟不倒退，不等于模拟真实拔插）：

```sh
cargo run -p rd-capture --example macos_probe --locked -- 0 --recreate
```

真屏回环（默认最大宽度 1920，保持纵横比并取偶数尺寸，30fps 上限）：

```sh
RDX_CAPTURE_DISPLAY=0 cargo run -p rd-app --bin rd-loop --locked
```

需要用户在 macOS 系统设置中授予屏幕录制权限。本轮不自动触发真屏采集，不修改系统权限。应用主页中的“本机桌面”仍为占位卡片，本轮只接通 rd-loop 开发验证入口。

## 验收边界

### rd-loop 前台/遮挡/隐藏对比与 50ms 预算分段

`rd-loop` 新增 `RDX_LOOP_HIDE_AFTER=1..120`（到时 `Visible(false)` 隐藏窗口）。合成源 24 秒限时运行（隐藏在第 12 秒；第 ~6 秒起窗口被桌面其他窗口完全遮挡），单轮内得到三种状态的对比；管道线程独立于 UI，全程 30fps 未停（pipeline_stopped=false）：

| 状态 | logic | draw 回调 | unique_draw | upload | superseded | 备注 |
|---|---|---|---|---|---|---|
| 前台 | ≈60/s | ≈56–60/s | 30/s | 30/s | ≈0 | 正常态 |
| 被完全遮挡 | ≈60/s | **0** | 0 | 30/s | ≈30/s | 逻辑仍按 vsync 运行，绘制回调不执行（表面不可见时 wgpu 取帧失败/跳过绘制），上传持续发生但全部被下一帧覆盖 |
| 隐藏 | 8.8/s | 0 | 0 | 8.8/s | ≈9/s | 定时器节流至约 9/s；upload 由 logic 驱动随之下降；GPU 完成回调停止注册 |

遮挡段由桌面实际状态触发而非受控放置窗口，归属解释需复测确认；但三段计数边界清晰。含义：**UI 遮挡/隐藏只影响显示侧**，捕获-编码-解码管道不受影响；被遮挡时上传照常发生（浪费带宽的雏形），恢复可见后随下一帧恢复。隐藏期 e2e p95 升至 38ms（上传节奏变慢所致）。

**受控遮挡复测（后续）**：rd-loop 限时 24 秒，第 3 秒以定位的无边框图案窗口（`RDX_PATTERN_X/Y/W/H=250/50/1300/760`）完全覆盖 rd-loop，第 10 秒隐藏覆盖窗。draw 计数精确跟随：遮挡生效秒 draw=0（logic≈60/s、superseded≈30/s），覆盖窗隐藏的下一秒 draw 恢复 36/s，随后回到 60/s 且 superseded=0。机制确认：完全遮挡时 wgpu 取帧失败/绘制回调不执行而逻辑照跑，解除遮挡即刻恢复；前一轮非受控观测的结论成立。rd-loop 窗口被遮挡期间上传照常 30/s（本轮 release 端到端实测亦为窗口被遮挡状态，531/531 指纹配对不受影响——指纹读自解码帧，与绘制无关）。

**50ms 预算分段判定**（PLAN P1 退出标准原文为“端到端延迟（捕获到上屏）< 50ms”）。已用内容归因指纹测得直接数据（见下节“回环内容归因端到端”，release 复测），综合判定：

| 分段 | 实测（release） | 说明 |
|---|---|---|
| 捕获→上传提交（编码+解码+CPU 提交） | p50 8.75 / p95 10.96ms | CPU 管道本体，余量充足 |
| 图案发布→捕获时间戳（呈现+合成+SCStream 交付） | ≈58ms（由 66.8 − 8.75 分解） | 与 present_probe 直接观测 49.5–50.3ms 交叉验证一致 |
| 上传提交→GPU 完成 | register→fire p50 ≈33.8ms | 含一次设备 poll 调度间隔，为上界；GPU 队列未积压 |
| 捕获→上屏（估算） | ≈49–67ms | = 编解码 8.75ms + 呈现/合成链（观测值扣除 SCStream 交付的测量侧贡献后 ≈40–58ms） |

结论：按“捕获到上屏”定义，现状 p50 约 49–67ms，临界至超出 50ms 预算；瓶颈在合成/呈现链（macOS 单窗口即 ≈2–3 个 60Hz 刷新周期），不在软编软解（release 仅 8.75ms）。两个方向（需决策）：(a) 维持定义，立项呈现侧优化（独占全屏、降低 vsync 等待、硬编减少 CPU 链路）后再验；(b) v1 预算放宽至 p50<80ms 并把“捕获→GPU 完成”（release p50 41.3 / p95 46.2ms，含调度上界）作为工程内控指标。P1 保持未验收。

### 回环内容归因端到端（指纹经解码帧读回）

rd-loop 新增 `RDX_LOOP_FINGERPRINT=1` + `RDX_LOOP_TRACE_FILE`：上传解码帧前从其 I420 Y 平面读回图案指纹（解码帧为捕获原分辨率，几何原生对齐；行偏移 `RDX_FP_Y_OFFSET` 适配无边框条带窗口的菜单栏下移，实测 30px），限时结束时与图案 trace 配对。本轮以 present_probe 5 秒预检确认图案可见（150/150 配对）后再跑主实验。

工具化过程发现并记录两个 macOS 陷阱：原生全屏窗口切独立 Space，其他窗口（rd-loop）聚焦后图案不在当前显示内容里——组合实验必须用无边框条带（`RDX_PATTERN_BORDERLESS=1 X/Y/W/H`）而非全屏；无边框窗口定位 (0,0) 的内容起点实际在菜单栏下方约 30px。此前“受控真屏 GPU 完成对照”一轮使用全屏图案 + rd-loop 同跑，图案很可能因 Space 切换未实际可见，捕获内容或为回环递归画面——该轮数值仍为有效动态内容测量，但“受控素材”定性存疑，本轮以可见性预检 + 530/530 配对取代。

本机 debug、顺序运行、单次采样（图案条带 1920×400@30fps 于显示器 0 顶部，rd-loop 捕获显示器 0）：

| 指标 | debug（20s） | release（20s，复测） |
|---|---|---|
| 指纹配对 | 530/530（100%） | 531/531（100%） |
| 图案发布→解码上传（含呈现+捕获+编解码） | p50 71.81 / p95 86.13ms | **p50 66.80 / p95 82.07ms** |
| 同轮捕获时间戳→上传提交 | p50 14.30 / p95 15.31ms | p50 8.75 / p95 10.96ms |
| 分解：呈现+采集链（发布→捕获时间戳） | p50 ≈57.5ms | p50 ≈58ms |
| 同轮 capture→gpu_done | p50 48.67 / p95 51.93ms | p50 41.33 / p95 46.20ms |

release 复测轮 rd-loop 窗口恰被桌面窗口遮挡（draw 仅 114 次），指纹读自解码帧不受影响，端到端数值有效。release 下编解码管道降至 8.75ms，呈现+采集链稳定在 ~58ms（与 present_probe 观测 49.5–50.3ms 的差异属运行间波动），确认该链路为端到端主导项且与构建配置基本无关。按“捕获到上屏”口径：8.75ms（编解码）+ 呈现/合成链（≈40–58ms，含观测侧 SCK 交付贡献）≈ p50 49–67ms，临界至超出 50ms。

运行中截屏经视觉确认：屏幕顶部棋盘格条带（帧号 #576）与 rd-loop 视频面板中嵌套的递归画面（含条带副本）同时可见，捕获→解码→显示链路视觉验证通过。边界：各单次采样、未控制其他负载；墙钟对齐（无 NTP 跳变假设）；分解值未做多次采样统计。

### 呈现观测与前台/隐藏对比

egui/wgpu 不暴露 Metal 上屏时刻，无法直接测呈现回调；改用**内容观测法**：pattern_window 以 `RDX_PATTERN_TRACE=1` 逐帧输出 `pattern-trace <帧号> <墙钟μs>`，右上角 8 个方块为帧号低 8 位指纹（几何按设备像素，绘制/读取共用 `rd-app/src/pattern.rs`，有往返单测）。`present_probe` 用 SCK 捕获同一显示器（max_width=8192 不缩放），从 Y 平面读回指纹并与 trace 对齐，输出“图案帧发布 → 被显示器内容捕获观察到”的时延；只统计指纹变化的观测（新内容到达），隐藏/冻结段单独检出（含末次转场后的尾段）。

```sh
RDX_PATTERN_FULLSCREEN=1 RDX_PATTERN_TRACE=1 RDX_PATTERN_SECONDS=26 \
  RDX_PATTERN_HIDE_AFTER=12 cargo run -p rd-app --example pattern_window --locked 2>/tmp/trace.log &
sleep 4 && cargo run -p rd-app --example present_probe --locked -- 0 20 /tmp/trace.log
```

本机 debug、顺序运行、单次采样（1920×1080，图案 30fps，探针请求 60Hz）：

| 阶段 | 观测 | 结果 |
|---|---|---|
| 前台（探针 0–8s） | 245 次转场，244 次配对 | 发布→捕获观察到 p50/p95/max = 50.3 / 57.7 / 61.1ms |
| 隐藏（`Visible(false)`，图案第 12s 起） | 转场停止 | 检出尾段冻结 11.9s，内容不再参与合成 |

release 复测（同参数）：回调内转换降至 0.45ms/帧（debug 7.9ms），但前台 p50/p95/max = 50.97 / 58.17 / 60.03ms，与 debug 几乎一致（帧时间戳在转换前采集，转换耗时本就不计入）；尾段冻结 10.8s。转换不再成为测量侧瓶颈，~50ms 主要来自图案渲染/呈现、窗口合成、显示刷新与 SCStream 交付链路，且该链路在单机本地窗口上即已 ≈3 个 60Hz 刷新周期。

图案窗口前台期 29.7/s 出帧；隐藏后 egui 仍以约 9/s 低频运转但指纹无任何变化。macOS 全屏窗口对 `ViewportCommand::Minimized(true)` 无响应（实测帧率不变），隐藏改用 `Visible(false)` 生效。

边界与解释：该时延包含图案自身渲染/呈现、WindowServer 合成、显示刷新与 SCK 采集交付，是**呈现时刻的观测上界**，非呈现回调；时钟为系统墙钟（非单调，短窗口内无 NTP 跳变假设）。对 P1 预算的含义：本地窗口“发布→捕获可见”已约 51ms，若预算测量点定义为“捕获→上屏”，须先明确预算点并把合成/刷新链路计入后再判定可行性；观测值中也含 SCStream 交付的测量侧贡献，无法从单次实验分离。rd-loop 窗口自身的遮挡/最小化对比仍待同法采样。P1 保持未验收。

### 受控动态素材与 GPU 完成测量

补齐此前缺失的两项测量前置：受控动态测试画面与 GPU 完成反馈。

新增 `rd-app/examples/pattern_window.rs` 受控素材窗口：图案完全由帧序号决定（逐帧整体翻转的棋盘底、匀速扫过的白条、帧号低 8 位黑白角标指纹、大号帧号），帧号按截止时间推进并重基错过节拍，与 vsync 重绘率解耦；不采集、不保存、不发送任何屏幕像素。

```sh
cargo run -p rd-app --example pattern_window --locked   # F 切全屏
RDX_PATTERN_FULLSCREEN=1 RDX_PATTERN_SECONDS=30 cargo run -p rd-app --example pattern_window --locked
# 可选：RDX_PATTERN_FPS=1..120（默认 30）
```

独立运行 10.00 秒出 299 帧（29.89/s，目标 30）。3 秒首跑出现过启动瞬态抖动，10 秒稳态正常。

GPU 完成测量：`video.rs` 在绘制回调内注册 `Queue::on_submitted_work_done`（同时在途至多一个），`stats.rs` 新增 GpuDone 记账。语义：回调在注册后的下一次设备 poll 触发，覆盖注册前已提交的全部命令（含当帧纹理上传），不含当帧绘制与任何呈现；register→fire 包含等待 poll 的调度间隔（约一帧），应视为 GPU 队列落后程度的上界指示而非纯 GPU 执行时长；capture→gpu_done 为捕获时间戳→队列清空，含本帧上传、不含本帧绘制与呈现。

本机 debug、顺序运行、采样期间无并行构建（真屏组为 pattern_window 全屏 22 秒 + rd-loop 限时 15 秒；rd-loop 窗口覆盖 pattern 一角，该区域构成局部画面回馈）：

| 来源 | 时长 | uploads | unique_draws / superseded | capture→upload p50/p95 ms | gpu_done 次数 | register→fire p50/p95 ms | capture→gpu_done p50/p95 ms |
|---|---|---|---|---|---|---|---|
| 合成源 1920×1080 | 10.01s | 299 | 298 / 1 | 7.02 / 8.67 | 306 | 32.09 / 38.13 | 40.98 / 47.40 |
| 真屏（pattern 全屏）1920×1080 | 15.00s | 431 | 431 / 0 | 10.35 / 11.53 | 447 | 33.69 / 35.75 | 44.75 / 48.39 |

pattern 窗口该轮 615 帧 / 22.00s（27.95/s）。真屏受控素材下 capture→upload 从此前非受控内容的 15.27/22.07ms 收紧至 10.35/11.53ms，说明此前波动主要来自桌面内容与系统负载。register→fire 稳定在约一帧（≈33ms），符合 GPU 队列未持续积压的预期；若 GPU 成为瓶颈该值会持续超过一帧并增长。capture→gpu_done p95 约 47-48ms 已接近 P1 的 50ms 预算，但仍不含本帧绘制与呈现，不能据此宣布端到端 <50ms 达标。

边界：单次运行、未控制其他系统负载、非 release 构建；呈现（presentation）时刻仍未测量；前台/遮挡/最小化对比未做（工具已具备：pattern 全屏 + 限时运行可复现该实验）。rd-app 18 项（含新增 GpuDone 单测）、rd-capture 10 项测试及 all-targets 严格 Clippy 通过。P1 保持未验收。

### 完整 release GPU 回环对照

使用独立目录构建 `rd-loop --release`，通过 `/usr/bin/time -l` 顺序运行两组 `RDX_LOOP_SECONDS=20`。本任务采样时未构建或同时运行另一组；未控制其他进程及桌面动态内容。两组正常退出（exit 0），pipeline_stopped=false。

| 来源 | UI 计时 | uploads / unique_draws / draws | superseded | 末次滚动上传 p50/p95 ms | 进程 real / user / sys 秒 | 最大 RSS bytes | peak memory footprint bytes |
|---|---|---|---|---|---|---|---|
| 合成源 1920×1080 | 20.01s | 598 / 597 / 1220 | 1 | 7.65 / 8.64 | 21.69 / 4.62 / 1.17 | 170541056 | 218121344 |
| 真屏 1920×1080 | 20.01s | 580 / 580 / 1367 | 0 | 7.75 / 16.54 | 20.23 / 3.96 / 1.08 | 178929664 | 220038272 |

按 UI 计时计算平均上传约 29.89 / 28.99 fps。按整个进程 wall time 计算 user+sys 约占一个逻辑核的 26.7% / 24.9%，不是整机 CPU 百分比，也不包含 WindowServer/捕获服务或 GPU 使用率。资源计时包括启动/退出，不能直接除以 UI 20 秒窗口。延迟是最后最多 256 个样本，而非全程分位数；源时间戳语义不同。

本轮只补 release 编译/运行验证，没有改动 UI 或捕获参数。可确认优化构建的真实上传/绘制回调路径正常工作；没有视觉截图、固定前台无遮挡证据及 GPU 完成/显示呈现反馈，不能将 CPU 提交延迟当成 <50ms 上屏验收。下一步优先补固定动态测试画面、前台/遮挡对比及呈现测量，P1 保持未验收，不启动 P2。

### 捕获链路计数诊断
