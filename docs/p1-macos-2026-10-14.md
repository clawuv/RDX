# macOS ScreenCaptureKit 接入基线

## 本轮实现

- 将仓库中未注册、未参与构建的 macos_sck 后端接入 rd-capture；依赖仅在 macOS 编译。
- 复用 RDX_CAPTURE_DISPLAY 显式选择本次显示器枚举的索引。未设置时继续使用合成源；非法索引报错，不回退至其他屏幕。
- SC 输出 420v/NV12，回调去行填充并去交织为 I420，复用现有 H.264 软编/软解与 GPU YUV 上传。仍有 CPU 拷贝，不是硬编或零拷贝。
- 用 watch 单槽替代四帧 FIFO，慢消费者读取最新画面。100ms 等待超时允许管道定期检查关闭，不把静态桌面未出帧判断为权限错误。
- 时间戳采用回环共用的 Instant，记录于 CPU 像素转换前；不代表桌面原始生成时刻或 GPU 呈现完成。
- 去掉本地 unsafe Send 声明，使用依赖自身的 SCStream Send 实现；检查平面高度、行跨度及尺寸乘法溢出。
- 输出尺寸变化返回 DisplayChanged；重建先释放旧流，再按原 display_id 精确匹配显示器，保持采集参数和共用时钟。原显示器缺失或 ID 重复则拒绝恢复，不以旧索引选取其他屏幕。现有管道有最多五次退避重试，耗尽后停止。display_id 只用于本次会话，不保证跨重启的永久身份。
- 接入原生流停止错误回调，优先报告错误而不是继续消费旧帧或永久超时。未区分可恢复的原生错误码，因此此类错误保守停止，权限撤销不自动重试。固定输出尺寸下的真实分辨率变化是否触发尺寸事件仍待实机验证。

## 手动验证入口

单帧探针（只输出尺寸/字节数/时间戳，不保存桌面像素）：

```sh
cargo run -p rd-capture --example macos_probe --locked -- 0
```

主动重建探针（采集前后各一帧，验证时钟不倒退，不等于模拟真实拔插）：

```sh
cargo run -p rd-capture --example macos_probe --locked -- 0 --recreate
```

真屏回环（默认最大宽度 1920，保持纵横比并取偶数尺寸，30fps 上限）：

```sh
RDX_CAPTURE_DISPLAY=0 cargo run -p rd-app --bin rd-loop --locked
```

需要用户在 macOS 系统设置中授予屏幕录制权限。本轮不自动触发真屏采集，不修改系统权限。应用主页中的“本机桌面”仍为占位卡片，本轮只接通 rd-loop 开发验证入口。

## 验收边界

### 完整 release GPU 回环对照

使用独立目录构建 `rd-loop --release`，通过 `/usr/bin/time -l` 顺序运行两组 `RDX_LOOP_SECONDS=20`。本任务采样时未构建或同时运行另一组；未控制其他进程及桌面动态内容。两组正常退出（exit 0），pipeline_stopped=false。

| 来源 | UI 计时 | uploads / unique_draws / draws | superseded | 末次滚动上传 p50/p95 ms | 进程 real / user / sys 秒 | 最大 RSS bytes | peak memory footprint bytes |
|---|---|---|---|---|---|---|---|
| 合成源 1920×1080 | 20.01s | 598 / 597 / 1220 | 1 | 7.65 / 8.64 | 21.69 / 4.62 / 1.17 | 170541056 | 218121344 |
| 真屏 1920×1080 | 20.01s | 580 / 580 / 1367 | 0 | 7.75 / 16.54 | 20.23 / 3.96 / 1.08 | 178929664 | 220038272 |

按 UI 计时计算平均上传约 29.89 / 28.99 fps。按整个进程 wall time 计算 user+sys 约占一个逻辑核的 26.7% / 24.9%，不是整机 CPU 百分比，也不包含 WindowServer/捕获服务或 GPU 使用率。资源计时包括启动/退出，不能直接除以 UI 20 秒窗口。延迟是最后最多 256 个样本，而非全程分位数；源时间戳语义不同。

本轮只补 release 编译/运行验证，没有改动 UI 或捕获参数。可确认优化构建的真实上传/绘制回调路径正常工作；没有视觉截图、固定前台无遮挡证据及 GPU 完成/显示呈现反馈，不能将 CPU 提交延迟当成 <50ms 上屏验收。下一步优先补固定动态测试画面、前台/遮挡对比及呈现测量，P1 保持未验收，不启动 P2。

### NV12 转换优化与 release 对照

移除逐行临时引用数组与 U/V 两次迭代追加，改为一次分配固定大小输出、按行复制 Y、单次 UV 遍历同时写入 U/V。保留现有指针边界校验，没有新增 unsafe 或 SIMD。新增 2/4/30/1920 字节行宽的 U/V 去交织参考对照测试，rd-capture 10 项测试及 all-targets 严格 Clippy 通过。

使用同一 macos_probe 参数、各 15.01 秒、本任务不并行构建：

| 构建/实现 | 帧数 | fps | 转换累计 μs | 转换均值 ms/帧 | 帧龄 p50/p95 ms |
|---|---|---|---|---|---|
| 上轮 debug 旧实现 | 438 | 29.18 | 5930968 | 13.54 | 13.72/14.21 |
| 本轮 debug 单次 UV 遍历 | 436 | 29.06 | 4634296 | 10.63 | 11.16/11.94 |
| 本轮 release 单次 UV 遍历 | 439 | 29.25 | 161603 | 0.37 | 0.37/0.64 |

三组消费者序号缺口及等待超时均为 0。debug 转换均值相较上轮下降约 21%，但桌面内容/系统负载未严格固定，不能作为受控性能提升承诺；release 没有测旧实现，不能把全部差异归功于算法改动。优化构建下转换已低于 1ms 量级，而出帧仍约 29fps，下一步应验证受控动态源与采集节拍/系统回调，暂不据此增加 SIMD 复杂度。完整 release GPU 回环、实际上屏及跨平台验收仍未完成。

### 捕获链路计数诊断

新增当前 stream generation 的回调数、有效发布数、读取数、读取前序号缺口与累计 NV12→I420 转换耗时。恢复时计数重置；原子快照在回调仍运行时不保证各字段同一时刻，不把 `published - consumed` 直接当成丢帧。序号缺口只覆盖本地 watch 槽，不能测量系统在回调前跳过的帧。

本机 debug、无本任务并行构建的 15.01 秒真屏探针：438 callbacks / 438 published / 438 consumed，skipped_before_read=0，29.18fps，超时 0。累计转换 5,930,968μs，平均约 13.54ms/发布帧；回调至读取帧龄 p50/p95=13.72/14.21ms。本次未出现消费者槽覆盖，不能由此解释此前不同桌面内容下的帧率差异；转换耗时值得进一步优化及 release 对照。仍非固定动态素材，不作为 30fps 或呈现验收。

新增序号缺口断言，rd-capture 9 项测试通过。

### 有时限的 GPU 回环运行

`rd-loop` 新增可选 `RDX_LOOP_SECONDS=1..120`：到时输出累计上传/绘制计数和最近 256 样本延迟并请求正常关闭窗口；未设置时保持原交互模式。该时限依赖 UI 调度，不是后台硬超时。

```sh
RDX_LOOP_SECONDS=20 cargo run -p rd-app --bin rd-loop --locked
RDX_CAPTURE_DISPLAY=0 RDX_LOOP_SECONDS=20 cargo run -p rd-app --bin rd-loop --locked
```

本机 debug、顺序运行、采样时未并行构建；两次正常退出，pipeline_stopped=false：

| 来源 | 时长 | 上传 | draw 回调 | unique draw | superseded | 末次滚动上传提交 p50/p95 |
|---|---|---|---|---|---|---|
| 合成源 | 20.01s | 600 | 1243 | 599 | 1 | 7.43/8.10ms |
| 真屏 | 20.03s | 560 | 1226 | 560 | 0 | 15.27/22.07ms |

合成源平均上传约 29.99fps；真屏约 27.96fps。superseded 仅统计上传后未绘制即被覆盖，不包含捕获/解码单槽覆盖。真实 wgpu 上传及绘制回调路径已运行，但未取得画面视觉验证、GPU 完成时间或呈现反馈；真屏桌面内容和遮挡条件未固定，不能认定稳定 1080p30 或端到端 <50ms。下一步需受控动态素材、前台/遮挡对比及 GPU/呈现测量，而非直接进入 P2。

### CPU 编解码回环基准（后续验证）

```sh
cargo run -p rd-codec --example loop_bench --locked -- synthetic 15
cargo run -p rd-codec --example loop_bench --locked -- mac:0 15
```

| 固定合成源 1920×1080 | 15.01s | 451/451 | 30.04 | 0 | 5.56/7.38 | 1.98/2.75 | 8.08/10.32 |

### 真屏探针实测（后续验证）

- 使用独立目录 `target/recovery-verification` 构建最新 macos_probe；运行 `macos_probe 0 --recreate` 正常退出。前后均取得 1920×1080 I420、3,110,400 字节，时间戳分别 246970 / 345056 μs。证明主动停止/重建后能再次取帧且共用时钟未倒退，不等同于真实拔插或权限撤销验收。
- 新增 `macos_probe 0 --seconds 20` 连续采样模式（1–60 秒），只统计尺寸、帧数、超时、时间戳与回调到消费者帧龄，不保存桌面像素。
- debug 实测 20.06 秒，531 帧，平均 26.47 fps，100ms 等待超时 5 次；callback_to_consumer_age p50/p95 为 13.85/18.17ms。未控制桌面动态内容，采样同时存在开发构建负载，不推断硬性性能上限；未满足稳定 30fps 验收。
- 帧龄包含回调内 NV12→I420 转换及等待读取，不含编码、解码、GPU 上传或屏幕呈现，不能当作端到端延迟。本轮未测 CPU/内存、硬编及完整 GUI 回环。
- 探针构建、严格 Clippy 与差异检查通过；未修改系统权限或显示器配置。
