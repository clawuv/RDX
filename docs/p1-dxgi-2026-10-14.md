# Windows DXGI 捕获基线

已实现显示器枚举、同适配器 D3D11 设备与输出复制、staging 纹理复用、BGRA 行紧缩，以及回环可选真屏来源。未将 P1 标记验收完成。

## 运行

枚举：`cargo run -p rd-capture --example dxgi_probe --locked`

单帧探针：`cargo run -p rd-capture --example dxgi_probe --locked -- 0`（1 为第二块显示器）。

PowerShell 真屏回环：

```powershell
$env:RDX_CAPTURE_DISPLAY = '0'
cargo run -p rd-app --bin rd-loop --locked
Remove-Item Env:RDX_CAPTURE_DISPLAY
```

未设置变量时仍使用合成源。显示器索引来自当次枚举，并非永久设备 ID。无效索引直接报错停止，不静默改用其他屏幕。

## 生命周期与限制

- Acquire 等待上限 100ms；超时表示无桌面更新，管道继续等待并可检查退出。成功 Acquire/Map 在 Result 错误路径上亦会 Release/Unmap。
- ACCESS_LOST 或尺寸变化映射为 DisplayChanged；管道清空待显示帧并触发有上限的资源重建，见下方恢复验证记录。
- 旋转屏幕拒绝；奇数尺寸在软编入口拒绝。鼠标指针独立形状未合成，脏矩形尚未优化，按完整桌面帧处理。
- GPU→CPU staging 拷贝与 BGRA→I420 CPU 转换属于基线路径，不是零拷贝/硬编。
- timestamp 是 Acquire 返回后的本机单调时间，不是桌面内容生成时间。显示的 capture_to_upload_submit 不包含完整桌面生成/等待时间，也不代表上屏延迟。
- 真屏只在桌面更新时出帧，不以静态桌面无帧推断捕获故障。回环采集节拍上限为配置帧率。

## 显示失效恢复（同日后续）

- RecoveringDxgiCapturer 在重建前释放旧 duplication，重新枚举并匹配原桌面设备名；缺失或重名时拒绝恢复，不回退到其他索引。设备名仅为当前会话标识，不保证跨重启或硬件重编号身份。
- DisplayChanged 最多重试 5 次，等待分别为 250/500/1000/2000/4000ms；UI 关闭会中断退避，耗尽后停止。其他采集错误仍停止，不自动提升权限。
- 恢复时发布空帧通知，UI 清除旧纹理；恢复后重新检查尺寸并重建编解码器，清空分段统计。奇数尺寸、旋转输出仍不支持。
- `cargo run -p rd-capture --example dxgi_probe --locked -- 0 --recreate` 本机成功：重建前后均取得 1920×1080 BGRA，8,294,400 字节，时间戳连续为 30292 / 68734μs。此探针主动调用恢复，未模拟真实 ACCESS_LOST。
- `cargo test -p rd-app -p rd-capture --locked` 共 19 项通过，其中新增恢复成功、5 次耗尽、UI 关闭取消退避及屏幕匹配边界测试。workspace/all-targets 严格 clippy、格式与差异检查通过。
- 尚待真实拔插/分辨率切换/锁屏触发的集成验证、恢复画面验收、指针合成及连续性能采样；未修改用户的系统显示设置。
