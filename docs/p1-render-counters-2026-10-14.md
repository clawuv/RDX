# P1 回环阶段统计补齐

本轮完成帧率诊断所需的 CPU 侧计数，不作为 P1 性能验收。

- logic：eframe 逻辑更新次数。
- upload：I420 三平面上传提交次数。
- draw：视频绘制回调提交 draw 命令次数，包含重复绘制同一帧。
- unique_draw：至少进入一次绘制回调的不同上传帧数。
- superseded：上传后尚未绘制就被下一次上传覆盖的帧数，不包含 watch 槽在 UI 读取前丢弃的帧。

每秒汇总由逻辑更新驱动，不再只在收到新帧时更新，因此管道停顿时上传率可归零。应用本身暂停调度时不能输出实时报告；恢复后按实际间隔计算平均值。延迟分位数仍是最近 256 个上传样本，不是当秒样本；无新样本时保留旧值。

绘制回调不是 GPU 完成或呈现反馈，不能据此认定达到上屏延迟目标。UI 已将 display fps 改为 upload / unique draw，并提示管道已关闭。

验证：cargo test -p rd-app --locked 共 6 项测试通过；cargo clippy -p rd-app --all-targets --locked -- -D warnings 通过；格式及 git diff --check 通过。新增测试覆盖重复绘制、无上传绘制和绘制前覆盖。

下一步：运行 rd-loop，在固定前台、无遮挡条件下采集统计，再与遮挡/最小化条件对比；本轮没有运行 GUI 性能采样。之后接入 Windows DXGI 捕获。真实捕获、GPU 完成/呈现计时、硬编和跨平台验证仍未完成。
