# P2 首周 spike：str0m 与 tokio 桥接（2026-10-15）

## 结论

**桥接模式可行**（PLAN.md P2 标注的最大不确定点，消除）。str0m 0.24.1 以纯 Rust crypto（`rust-crypto` feature）接入 rd-transport（feature `webrtc`，默认关闭，wasm 侧不拉入原生依赖）：同步 `Rtc` 与其 UDP socket 全部归一个专用线程，tokio 侧只通过 channel 交互（命令进、事件出），线程内按官方 chat 示例的 poll_output/Transmit/Timeout 模式驱动。本机双实例经**真实 ICE + DTLS + SCTP** 在 127.0.0.1 UDP 上建立 DataChannel 并双向交换帧，4 项测试 0.6 秒通过（含握手）。

## 实现要点（crates/rd-transport/src/str0m_impl.rs）

- `Str0mTransport`：实现 `Transport` trait（send/recv Frame）；事件通道同时暴露 `ChannelOpen`/`IceConnected` 生命周期事件供上层观测。
- SDP 交换属信令（P3）：`new_offerer`/`new_answerer`/`accept_answer` 显式传递 offer/answer；`connect_pair` 以进程内交换完成握手，供 P2 局域网联调与测试。
- 发送路径：命令只入队，线程在通道打开后按 SCTP 可用窗口（`Channel::write` 返回 false 即背压）冲刷；tokio 侧从不阻塞。
- 接收路径：`Event::ChannelData` 直接推送事件通道；recv 跳过生命周期事件。
- 线程退出：Shutdown 命令或命令通道断开（try_recv Disconnected）即结束，`Drop` join 至多一个轮询周期（≤100ms）。
- 期间踩坑记录：tokio 运行时线程上不可 `blocking_send`（用 try_send + 断开兜底）；`Input::Receive(Instant, Receive)` 而非旧文档的 `Input::Packet`；锁文件重解析遇 zeroize_derive 索引缓存陈旧，`cargo info` 刷新后自愈。

## 验证

- `cargo test -p rd-transport --features webrtc`：4 项通过（双向帧交换 + 线程干净退出）。
- `cargo clippy -p rd-transport --features webrtc --all-targets -- -D warnings` 通过；默认 feature（不拉 str0m）构建与测试不受影响。
- wasm 核心边界复验：`rd-protocol` / `rd-engine` / `rd-crypto` 在更新后的锁文件下仍编译 `wasm32-unknown-unknown`（本机此前未装该 target，已补装验证）。

## P2 正式接入前待办

- Frame 分片/重组规格（PLAN P2 已列）：当前实现按 SCTP 窗口整块写入，无应用层分片；通道 MTU 与每通道字节上限按 P2 分片规格落地。
- 平台 crypto 后端评估：纯 Rust 可移植，性能与 apple-crypto/wincrypto 的对比留待实测。
- ICE 重启/重连与 rd-engine 会话状态机联动（P2 会话 actor 接入时）。
- 真实跨机（局域网两台机器）联调；TURN（coturn）路径 P3。
