# Windows 真屏连续编解码验证

新增 `dxgi_roundtrip` 探针：枚举指定输出，DXGI 取 BGRA，OpenH264 编码/解码，校验尺寸、I420 布局和原始单调时间戳。只统计 CPU 捕获、编码、解码；不宣称 GPU 完成或屏幕呈现。

## 结果

- 动态测试窗口运行 20 秒，目标 30fps，实际图案窗口平均 28.60/s。
- Debug 真屏回环 10 秒：207 个解码帧、17 次无更新超时、20.68fps；capture 调用 p50/p95=5.55/16.13ms，encode=15.93/49.89ms，decode=3.04/9.68ms，捕获到解码完成=24.57/63.69ms。
- Release 探针在静态桌面 10 秒：8 个解码帧、88 次超时；capture=4.45/11.89ms，encode=51.78/85.58ms，decode=8.77/17.54ms，捕获到解码完成=64.84/107.19ms。静态桌面没有持续更新，不能用于 30fps 性能结论；少量样本显示 release 编码受当前机器状态影响较大。
- 每个成功解码帧均通过宽高、I420 字节数、格式和时间戳单调性校验；未写入像素文件。

## 结论与剩余项

真屏 BGRA→H.264→I420 路径已可运行，已取得下述同屏 release 动态样本，但没有稳定达到 30fps，不能把 P1 标记为通过。需要继续运行完整 GUI 上屏链路，分别记录 CPU、GPU 完成与内容观测延迟；还需验证指针画面、锁屏/拔插恢复和内存峰值。

## 同屏 release 复测与跳帧修复（2026-10-15）

- 核实本机显示布局：DXGI index 0 为 DISPLAY2，物理坐标 (0,0)、1920×1080、主屏；index 1 为 DISPLAY1，坐标 (1920,0)。先前在 (100,100) 启动图案却采 index 1 的测试没有采到图案，应排除出受控性能对比。探针现输出桌面原点，便于复核。
- 同屏测试暴露 OpenH264 码率控制跳帧被包装为空 packet 的缺陷，解码报告 `decoder needs more data`。编码器现返回空 packet 列表，探针记录 `encoder_skipped` 并继续；未禁用码率控制，也未吞掉解码错误。低码率 90 帧回归测试实际触发跳帧，并验证所有非空 packet 可解码且时间戳匹配。
- 修复后：release pattern 在 (100,100)、980×640 窗口运行 30 秒，3 秒后并行采 index 0 共 20 秒。只覆盖部分桌面；图案更新计数不等于实际呈现计数。两个进程均正常退出。
- 真屏回环：20.01 秒、526 个解码帧、4 次无更新超时、8 次编码跳帧、26.29fps、4,834,124 编码字节。全部解码帧通过格式、尺寸、字节数和时间戳校验。
- 最近 256 个样本 p50/p95：capture 调用 4.73/9.36ms；encode 14.29/35.49ms；decode 2.75/7.89ms；Acquire 返回到解码完成 21.87/52.17ms。各指标独立滚动，不能相加推导分位数。
- 图案完整 30 秒共 628 次更新、20.93/s，未稳定达到目标 30fps；回环包含其他桌面/指针更新，因此 26.29fps 不能解释为唯一图案内容帧率。此样本证明动态链路能持续运行，不满足固定 1080p30 素材验收条件。
- 日志保存在构建目录 `target/p1-pattern-release-fixed.log` 和 `target/p1-roundtrip-release-fixed.log`，未保存桌面像素。测量未包含 GPU 上传、GPU 完成或呈现。
- 修复后 `cargo test --workspace --locked` 全部 55 项单元测试及文档测试通过；release 探针构建、`cargo fmt --all -- --check` 与 `git diff --check` 通过。
- `cargo clippy --workspace --all-targets --locked -- -D warnings` 通过。
