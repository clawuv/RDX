# v1 威胁模型与认证决策（草案）

- 状态：草案（P0 门槛项）——**未经评审不得视为已定实现规格**；评审通过后修订 ADR-0005。

## 1. 资产与目标

- 机密性：会话媒体流、输入事件、剪贴板内容对服务器与第三方不可见。
- 完整性：输入/控制指令不可被篡改注入。
- 身份：控制端连到的确实是声明的受控设备（防服务器或网络中间人顶替）。
- 可用性：尽力而为，DoS 缓解不作为安全承诺。

## 2. 参与者与信任假设

| 参与者 | 信任 |
|---|---|
| 信令服务器（hbbs 角色） | 不可信载荷：可拒绝服务、可见元数据（ID、IP、在线状态）、可尝试中间人。不得有能力解密或顶替端点。 |
| TURN 服务器 | 同上，纯转发，只见密文。 |
| 用户自己的两端设备 | 可信（远程桌面本身即授权对方完全控制，端点恶意属于授权问题，不在威胁模型内）。 |

## 3. 威胁与对策

| 威胁 | 对策 |
|---|---|
| 服务器 MITM 顶替端点 / 偷换密钥 | 会话加密密钥仅由两端协商（Noise）；端点身份由设备密钥对签名认证（见 §4）；首次连接带外指纹校验 + 受控端确认弹窗；P6 加公钥透明日志。 |
| 口令在线猜测 | v1 不承载"弱口令即安全"的承诺（见 §4 决策）；认证失败指数退避 + 每设备失败计数锁定；OPAQUE（服务器不持明文口令，注册记录仍属需保护的认证材料）P6 落地后口令才成为一等认证因素。 |
| 重放 | 握手含双方随机数 + 会话唯一序号；握手 transcript 签名，旧握手无法迁移。 |
| 降级（旧协议版本/弱套件） | 版本协商只取双方共同最高版本，且版本号进入签名 transcript；不存在"兼容模式回退"。 |
| 传输层配置错误 | Noise 加密不依赖 WebRTC DTLS 配置正确；即使 DTLS 被错误终止，媒体面仍是密文。 |

## 4. 历史候选方案（开发范围已由第 6 节收敛）

**禁止项**（无论选哪项都适用）：自行拼接"口令哈希/派生密钥 + Noise"并视为已认证——没有 PAKE 结构的口令方案无法抵抗字典攻击，一律不做。

- **方案 A（推荐）**：v1 身份 = 每设备 ed25519 密钥对；握手 = Noise_XX（交换静态公钥并签名 transcript）；首次连接由用户通过可信带外渠道核对完整公钥指纹（具体绑定见第 6 节），受控端弹确认框作为在线防线。口令/账户体系整体推迟到 P6（OPAQUE）。MVP 认证承诺 = 设备身份 + 带外核验，不含口令。
- **方案 B**：v1 直接上 OPAQUE（提前到 P4）。安全性最好，但注册流程 UX + 审阅成本可能拖 MVP 1-2 周。
- **方案 C**：v1 缩小到"仅限物理接近场景"（类似初次配对扫码），完全不做远程身份声明。最省，但产品价值受损。

若 P4 前评审无法完成，按方案 A 的"不含口令"承诺收缩 MVP 范围，不降低认证强度。

## 5. 与计划的联动

## 6. 本轮收敛的 MVP 工程范围（2026-10-14，待协议安全评审）

选择方向：设备配对 + Noise。本节替代第 4 节的“三选一”作为开发范围，不表示协议已获独立安全评审。密码学实现仍被评审门槛阻断。

- 首次配对必须在两个端点由用户确认，并通过可信带外渠道核对完整设备公钥指纹或 QR 数据。旧文“6 位指纹”不再作为认证规格。设备 ID、服务器目录结果、点一次允许均不能单独证明身份。
- 候选 Noise_XX 的静态密钥必须与已核验身份绑定。算法套件、设备签名键与握手静态键的关系、规范化编码、签名上下文、转录绑定的具体格式须审阅后定稿，禁止临时拼接。
- 未完成双方认证与确认前，不能启用媒体、输入或剪贴板；协商版本、能力及会话随机数必须被认证转录覆盖。重连重新握手，不沿用旧会话密钥、授权或输入队列。
- 已配对设备固定绑定密钥；密钥改变必须中止连接并重新走带外配对，禁止普通警告弹窗后继续。
- 权限按会话、按能力授予；受控端始终可以撤销。断开或撤销后清除会话授权，取消尚未执行的输入，首次连接不允许无人值守。
- 删除配对即拒绝该身份新连接并结束现存会话；私钥丢失不由服务器恢复，按新设备重新生成和带外配对。不在 v1 提供账户口令、找回密码或服务器托管私钥。
- 握手、未认证连接、失败重试和消息体均须有资源上限、超时与退避；每 IP 限制不能替代设备/全局上限。具体数值在 P4 压测与安全评审时确定。
- 服务器只负责寻址/中转，不能授权设备、重置端点信任或静默更新密钥。日志不记录密钥、口令、媒体或完整敏感转录。
- OPAQUE、账户体系和公钥透明日志移至后续独立设计；仅发布 Merkle head 不构成完整防替换机制。
