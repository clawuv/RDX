# P3 执行计划：公网可用（2026-10-15）

- 状态：计划（未开工）。工期 4 周 × 2 人；单人约 7 周。
- 上游状态：P1 未整体验收、P2 规格未冻结，按既定指示继续推进，P3 不以 P1/P2 收口为前置；P3 对 P2 的真实依赖面见 §5。
- 本计划制定时完成的一项关键事实核查：**str0m 0.24.1 不自带 TURN 客户端，也不做候选收集**（README「NIC enumeration and TURN」节明确将 TURN 等同于 NIC 枚举、归用户负责；本地锁定的 `is-0.11.1` 提供 STUN 编解码与 allocate/refresh/create_permission/channel_bind 消息构建器，但无分配生命周期状态机）。当前 `str0m_impl.rs` 只添加 127.0.0.1 host 候选。因此 **srflx 收集与 TURN 中继路径是 P3 唯一无先例背书的技术点**，按 P2 首周 spike 的模式在 P3 首周证伪（见 §3 W1 与 §6 决策 1）。

## 1. 范围

对照 PLAN.md P3 条目，交付四件事：

1. `rd-server` 信令服务：axum + WebSocket，只做 ID 注册/寻址、SDP/ICE 中转、在线状态。存储 Postgres（sqlx，devices 表），presence 为连接内存态。v1 单实例；消息流程与无粘性 presence 设计为按 ID 一致性哈希水平扩展留缝，但**不实做**扩展。
2. coturn 部署与 TURN 凭证签发：coturn `use-auth-secret` + static-auth-secret；rd-server 按 TURN REST API 规范代签时限凭证（`username = "<unix 到期>:<设备ID>"`，`password = base64(HMAC-SHA1(secret, username))`，有效期 ≤10 分钟）。不自建中继（ADR-0002）。
3. 客户端侧候选收集与中继：srflx（向 coturn STUN 发 binding request，`is` 已有构建器）、relay（TURN 客户端，路线首周决策）、经信令通道的 SDP/candidate 交换编排。
4. NAT 打洞验证矩阵与公网真实验收（§4）。

**不做进 P3**：端到端认证与设备配对（P4，threat-model §6 评审门槛未被触碰）、OPAQUE/账户（P6）、水平扩展实做、TURN over TCP/TLS 443（若实测 UDP 阻断频发再评估，属范围变更需 ADR）、多区域部署、Web 端（P8）。

**安全边界声明**：信令服务器按威胁模型属不可信载荷方。P3 期间服务器中转的 SDP/candidate 没有端到端认证保护，**公网连通是连通性验收，不构成安全验收**；服务器实现须遵守"日志不记录 SDP/候选/消息载荷"的既定约束。P3 若引入设备公钥（§6 决策 2），仅作为服务器侧 ID 一致性机制，不得宣称为认证。

## 2. 架构决策基线（首周冻结为 ADR-0008）

- 信令消息：rd-protocol 新增 protobuf 定义（prost，当前尚未引入依赖），WebSocket 二进制帧承载。消息族：`Register{device_id, pubkey?}` / `RegisterResult` / `Signal{target_id, opaque_payload}` / `SignalError` / `PresenceEvent` / `Heartbeat`。服务器对 `Signal` 载荷**不解析**，仅施加大小上限（如 64KiB）与速率限制；SDP 与 ICE candidate 均为不透明 blob。
- ID：客户端生成随机 ID（建议 ≥51 bit 熵的字母数字串），服务器查重；在线期间同 ID 重复注册拒绝。防抢占最小机制见 §6 决策 2。ID 仅用于寻址，不承载身份语义（threat-model 已定，不重开）。
- 在线状态：WS 连接即在线；应用层心跳超时（30–60s）清理并通知等待方。presence 不落库（重启丢在线态可接受，客户端自动重连），devices 表仅存注册信息与 last_seen。
- 中继流程：caller 经服务器向 callee 投递 offer → answer 回程 → candidate 双向转发直至 ICE 完成；此后数据面完全脱离服务器（P2P 或 TURN）。
- 部署形态：单 VPS，docker-compose（rd-server + Postgres + coturn + caddy 提供 WSS/TLS）；STUN 与 TURN 同用 coturn 3478/udp。
- TURN 客户端路线（三选一，首周 spike 后定）：(a) 基于 `is` STUN 构建器自研最小 TURN 客户端——点对点远控只需单 allocation、单 peer 的 allocate/refresh/create_permission(+channel bind)/数据收发子集；(b) `turnclient` crate；(c) webrtc-rs `turn` crate（tokio 重，与 str0m 专用线程模型存在阻抗）。评估维度：与 sans-io 专用线程的适配、维护面、许可进 deny.toml 白名单。

## 3. 周计划（A 线＝服务端/部署，B 线＝客户端/传输；两人可互换）

### W1：协议与双 spike
- A：rd-server 骨架——axum + WS + 内存 presence + devices 表迁移（sqlx）；Register/Signal/Presence 消息实现；集成测试：真实服务器进程 + 两个客户端完成 offer/answer/candidate 中转。
- B：候选收集 spike——srflx 经 coturn STUN binding；relay 三路线评估与冒烟（本地 coturn，两实例强制仅 relay 候选建立连接并传帧）；rd-transport 信令客户端（tokio-tungstenite），`connect_pair` 的进程内交换之外新增经真实信令的编排路径（`connect_pair` 保留为测试设施）。
- 共同：§6 决策清单全部过一遍；ADR-0008 成文。
- **里程碑**：局域网两台机器经真实 rd-server + 本地 coturn relay 冒烟路径连通传帧（同时构成 P2「跨机联调」缺项的首个真实场景）。

### W2：公网部署与重连
- A：VPS 生产化部署（compose + TLS + 重启策略 + 日志轮转）；HMAC 凭证签发（§2 格式）；基础指标（连接数、消息量、凭证签发数）与结构化日志（不含载荷）。
- B：完整候选注入（host + srflx + relay）与 ICE server 配置进 `Str0mTransport`；ICE restart 断线重连经信令重协商打通（engine 状态机最小联动）；TURN 凭证过期刷新。
- **里程碑**：两台机器经公网 VPS 的信令 + coturn 全流程连通；记录 ICE 选中路径（host/srflx/relay）与连接建立时长。此阶段不刻意构造对称 NAT，能连即达标。

### W3：NAT 矩阵与劣化网络
- 环境（A 搭建）：≥2 个真实家庭网络实测；Linux netns + nftables 构造 EIM（锥形）与 EDM（每目标独立映射，对称）两类 NAT；云多区域节点按需补充。tc netem 加 1–5% 丢包、50–150ms 延迟档位。
- 测试（B 执行）：组合至少覆盖 锥×锥（应直连）、锥×对称、对称×对称（应 100% TURN）；每组合记录候选类型、选中路径、连接建立时长、≥30 分钟稳定性。劣化档位下验证分片重组丢帧恢复与 KeyframeNeeded 联动（P2 缺项在真实网络补测）。
- 产出：矩阵文档（含模拟方法与已知偏差声明）。
- **里程碑**：对称×对称组 100% 经 TURN 建立且可用。

### W4：硬化与验收
- 服务器：注册/中转/凭证签发限速、消息大小上限、每连接并发等待上限、心跳超时清理的资源上限测试。
- 客户端：信令断线重连、服务器不可达的 rd-app 最小状态呈现。
- 验收与文档：§4 清单全项执行；部署手册（compose、TURN secret 轮换）、运维 runbook、`docs/p3-validation-2026-10-15.md` 验收记录；更新 PLAN.md。

## 4. 验收标准（对照 PLAN.md P3 退出标准）

1. 两个不同家庭网络的机器经公网信令成功连接并稳定传帧（真实公网，非模拟）。
2. 对称 NAT 场景 100% 走 TURN 且可用：模拟环境必做；真实对称 NAT 网络尽力寻测，找不到则在验收记录中明示限制。
3. 量化记录（性能预算表贯穿性要求）：连接建立时长 p50/p95、各 NAT 组合 ICE 路径分布、公网 1080p30 延迟与丢帧观测（记录项，非 P3 硬门槛）。
4. rd-server 集成测试：注册冲突、离线抢占策略、中转大小/速率上限、心跳超时清理。
5. 安全边界重申：不宣称任何认证/加密验收；服务器日志经检查不含载荷明文。

## 6. 开工首周决策清单

1. **TURN 客户端路线**（§2 三选项）——P3 最大不确定点，spike 数据驱动。
2. **ID 防抢占最小机制**：推荐 Register 携带设备 ed25519 公钥、同 ID 重注册须私钥签名自证（需 rd-crypto 提供最小密钥对/签名工具；属服务器侧一致性，非端到端认证，不触碰 threat-model §6 评审门槛，也不得对外表述为认证）；退路为服务器随机分配未占用 ID + 抢占行为仅记录。
3. 信令编码：protobuf over WS binary（rd-protocol 既定方向，默认通过）。
4. TURN 凭证下发时机：倾向随 Register 应答附带，减少往返；单独 REST 拉取作备选。
5. presence 粒度：内存态 + devices.last_seen 落库（默认通过）。
6. ADR-0008：信令服务边界、消息族与"服务器不解析 Signal 载荷"约束成文。
