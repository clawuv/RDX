# ADR-0003: 控制面 protobuf，数据面裸帧，帧绝不进 protobuf

- 状态：已接受
- 日期：2026-10-13

## 背景

RustDesk 把视频帧塞进 protobuf 消息（`VideoFrame { Vec<u8> }`），每帧多两次分配拷贝；控制消息与媒体消息走同一封装，解析路径耦合。

## 决策

- 控制面（握手、能力协商、权限、输入事件、剪贴板）用 protobuf（prost），握手时协商协议版本 + 能力位，演进只做增量。
- 数据面媒体帧用裸帧，不经 protobuf。当前实现中的 `[stream_id:u8][flags:u8][seq:u16][len:u32]` 是候选帧封装，不是最终 WebRTC DataChannel 分片格式。
- 无序/不可靠视频 DataChannel 的线上分片头必须能关联帧序号和分片索引/总数（或有等价、可验证的分片完成语义）；每会话/每帧有字节数、并发重组数和存活时间上限。任一分片丢失或过期即丢弃整帧，不能等待它阻塞后续帧。
- 头部定义与编解码在 `rd-protocol::frame`，含最大载荷长度上限（防 DoS）。

## 后果

- 媒体路径零序列化开销；控制面保留跨语言 SDK 友好性。
- 当前头部的 `LAST_SLICE` 单独不足以标识无序分片；P2 完成乱序/丢失/重连和资源上限测试后，才冻结线上布局。冻结后通过版本/能力协商演进，不假定 flags 可以承载所有未来扩展。
