# ADR-0005: 认证 OPAQUE，会话加密 Noise，端到端直通

- 状态：已接受
- 日期：2026-10-13

## 背景

RustDesk 的口令认证 + "密钥变了"弹窗属于手工 TOFU（首次信任），服务器理论上可偷换密钥。目标是端到端加密、服务器只见密文，且认证阶段服务器也拿不到口令等价物。

## 决策

- 认证：OPAQUE（opaque-ke，PAKE 协议）是候选口令认证方案。服务器不持有明文口令，但必须保存 OPAQUE 注册记录；该记录仍是需保护的认证材料，不能描述为“服务器不存任何口令等价物”。
- 会话加密：Noise 框架（snow）建立会话密钥，控制与媒体全链路加密；传输层 WebRTC 自带 DTLS，Noise 层保证不依赖传输配置。
- 设备公钥目录 + 简单透明日志（签名追加的 merkle head 定期公布），防服务端偷换密钥。
- P0 威胁模型必须定义服务端信任假设、设备身份绑定、Noise 握手身份认证与 transcript 绑定、重放/降级/在线猜测防护、速率限制和账户恢复。不得把口令哈希/派生密钥直接拼接 Noise 当作经过认证的 PAKE。
- P4 的具体认证组合须经协议审阅后确定；若 MVP 采用口令，则使用经审阅的 PAKE 与限速策略。否则须明确采用何种设备配对/身份验证并收窄产品承诺。OPAQUE 注册、设备目录及透明日志的协议和恢复流程在实现前单独评审。

## 后果

- 密码学依赖面小（opaque-ke + snow + 标准曲线库），全部走审计过的实现，不自造密码学。
- OPAQUE 注册流程需要服务端注册记录、首次设备绑定、恢复/换机与防目录回滚设计；透明日志还需客户端一致性验证。不能仅以发布 Merkle head 作为防偷换的完整实现。
