# ADR-0007: P1 延迟预算口径调整——v1 以 p50<80ms（捕获到上屏观测）为目标

- 状态：已接受（2026-10-14 由继续开发指示代拟，可推翻）
- 日期：2026-10-14

## 背景

PLAN.md P1 退出标准原文为“1080p30 端到端延迟（捕获到上屏）< 50ms”。本轮已具备直接测量手段（docs/p1-macos-2026-10-14.md）：

- 内容归因指纹端到端（release，531/531 配对）：图案发布→解码上传 p50 66.8ms；其中编解码管道 8.75ms、呈现+采集链 ≈58ms。
- present_probe 独立交叉验证：本地窗口发布→被显示器内容捕获观察到 p50 49.5–50.3ms（≈2–3 个 60Hz 刷新周期）。
- 瓶颈确凿在 macOS 合成/呈现链，不在软编软解；该链路在单机本地窗口上即已接近原预算全额。

维持 50ms 字面口径将使 P1 无法在当前 egui/wgpu + 合成器路径下退出，且“上屏”时刻在 wgpu/egui 现有 API 下不可直接观测，只能以内容观测法取上界。

## 决策

1. v1 预算调整为：**捕获到上屏（内容观测法）p50 < 80ms**；P1 退出标准同步修改。
2. 工程内控指标：**捕获→GPU 完成（on_submitted_work_done 观测）p95 < 50ms**（release 现测 p50 41.3 / p95 46.2ms，含一次 poll 调度上界）。
3. 呈现侧优化（独占全屏呈现、降低 vsync 等待、硬编缩短 CPU 链路）登记为 v1 后优化项；若后续把 p50 压回 50ms 以内，可按本 ADR 的逆过程恢复原口径。
4. 所有“上屏”类验收数据必须注明测量方法（内容观测法）与包含的链路（合成、显示刷新、观测侧 SCStream 交付），不与 GPU 完成类指标混用。

## 后果

- P1 可在数据充分的前提下按新口径验收，避免为单一口径无限期阻塞。
- 80ms 是基于实测（66.8ms p50 + 余量）的工程目标，非外部承诺；对外宣传延迟需另行定义测量条件。
- 风险：50ms 目标名存实亡，可能永久停留在“后优化”；以内控 p95<50ms（捕获→GPU 完成）约束工程不退化。
- 测量侧（SCStream 交付）贡献未从观测值中分离，80ms 口径内含测量上界成分；多次采样与分离测量留待后续。
